# Oral exam (Realtime) — detail

> Extraído do `replit.md` em 25/07/2026 para mantê-lo enxuto. Este arquivo é a fonte de detalhe do subsistema de prova oral; atualize AQUI quando ele mudar.

A second work kind (`works.kind = 'oral_realtime'`) runs a spoken, camera-on exam over OpenAI's Realtime API. It is deliberately **not** the interview architecture:

- **Relay, not orchestration.** `lib/oralRealtime.js` attaches a WebSocket relay (browser ↔ server ↔ OpenAI Realtime). The server only forwards PCM audio and tracks a response-latency signal; the conversation runs on `gpt-realtime`. The gabarito never reaches the browser/Realtime — only the questions (a per-student sample when N < total, persisted in `oral_asked_json`). The transcript is recorded in **conversation order** (a placeholder is reserved when the student's item enters the conversation, because input transcription arrives late — otherwise the record interleaves wrongly).
- **A voz precisa ser do Realtime, e a configuração é confirmada antes de o modelo falar (#351).** `config/voices.js` marca cada voz com `realtime: true|false`: `nova` e `onyx` a TTS aceita e o modelo Realtime **rejeita**. A rejeição não é local — a OpenAI recusa o `session.update` **inteiro**, então instruções, questões e a ferramenta de encerramento não entram, e a arguição roda com a personalidade padrão do provedor, em inglês. Aconteceu no dev em 31/08/2026 e só apareceu no log. Três barreiras: a UI só oferece vozes compatíveis (`voicesFor({realtime:true})`), o save recusa incompatível (`POST /w/:t/oral/config`), e o relay cai no `FALLBACK_VOICE` se o valor gravado for antigo. Além disso, `lib/realtimeBridge.js` **espera `session.updated`** antes do primeiro `response.create` (timeout de 8 s degrada para o comportamento anterior, com log) e, enquanto a sessão não estiver confirmada, um `error` da OpenAI **encerra a sessão** com `ended/config_rejeitada` em vez de deixar o agente padrão conduzir — uma prova que não abre é problema visível; uma prova conduzida pelo agente errado passa por válida.

- **Guaranteed ending (the exam always closes with speech).** The farewell is **100% system-owned**: the examiner is prompted to acknowledge the last answer in half a sentence and call `encerrar_prova` immediately (explicitly told NOT to say goodbye nor announce "let me think/conclude" — asking the model for the farewell failed three ways in real exams: silent tool call, barge-in cancellation, and wrong content). On tool acceptance the relay enters **ending mode** — no more turns: VAD is disabled via `session.update` and "listening" events stop reaching the client (no more audio flush). After the tool-call response's `done`, the relay ALWAYS speaks the fixed farewell via TTS (`pcm` 24kHz, exam voice) and only then sends `wrapup`. Ending lifecycle, barge-ins and silence-watchdog nudges are all logged.
- **Setup gate runs in the browser.** Before the exam, `static/oral-student.html` loads MediaPipe Tasks WASM (self-hosted in `static/vision/`) to check position (pose/distance/centering), hands visible, and phone presence — plus a Web-Audio noise meter and an RTT connection test — all client-side, so the server carries no per-student detection load (scales to many simultaneous exams). Position checks also run DURING the exam since #267 (ADR 0021): the same pose tick that feeds the presence signal drives a light posture watch (`static/js/liveNudge.js`) — 10 s of sustained bad posture pauses the session (`posture_lost`/`posture_ok` to the relay, self-resolving modal with the canonical position photos; never spoken by the examiner), with a built-in inference budget that disables the watch on slow machines (state + pauses reported to the professor via `oral_voice_json.live_nudges`). Noise only gates the start. **Exceção: o vídeo é OBRIGATÓRIO e BLOQUEANTE** (migration 072, 2026-08-14) — `static/js/proctorGate.js` confirma a captura antes de conectar ao relay (inicia o `MediaRecorder` e só abre o WebSocket após o 1º chunk; sem gravação → bloqueia); se a câmera cai no meio, o cliente manda `{type:'capture_lost'}` e o relay (`lib/realtimeBridge.js`, flag `paused`) suspende o encaminhamento do áudio do aluno até `capture_ok`; no fim, `onCleanFinish` passa por `finalizeWithVideoGate` — sem vídeo a sessão fica `awaiting_video` até o `POST /s/:t/oral/video` chegar (`promoteAwaitingVideo`). O professor pode liberar sem vídeo (`waive-video`). **Retomada pós-queda exige liberação** (#260, ADR 0020): se a sessão caiu com fala do aluno registrada, a próxima conexão é rejeitada (`resume_blocked`, `lib/resumeGate.js`) até o professor liberar (`allow-resume`, consumido atomicamente na reconexão — `resume_allowed_at`, migration 075). Mesma mecânica na entrevista simplificada (`/live/*`). **Tee + retranscrição (#289)**: the relay tees the student's continuous PCM to disk (`lib/audioTee.js`; boundaries marked from the relay's own clock; any failure = log, never touches the relay), converts to OGG post-session, stores it, and fires a background retranscription (`lib/retranscribe.js`, provider layer #284 + mechanical glossary #293) into `submissions.final_transcript` — audit record shown to the professor, NOT yet the evaluation source (convivência per the 21/08 strategy).
- **Sound check (pre-test, browser) — v2 em escada (#288, ADR 0023), GUIADO POR VOZ desde #321 (adendo 2)**: um wizard com áudios pré-gravados do "orientador" (`static/audio/soundcheck/`, gerados de `lib/soundCheck.js#SC_SCRIPTS` por `scripts/gen-soundcheck-audio.mjs`) conduz silêncio → veredito conexão/ruído ("Estou ciente" quando há problema) → fones+eco → leitura; **cada fala da voz-guia é sonda de eco** (vazamento medido contra o roteiro conhecido, `scriptLeakMatches`), 1º eco repete o estágio e 2º eco = vermelho. Three probes before the voice session, all recorded into `submissions.oral_calibration_json`: (1) **leitura** — if the work has a calibration sentence (`works.oral_calibration_json`, generated by `OralCalibrationAgent`), the student reads it aloud; the server transcribes with the SAME STT used for grading (`POST /s/:t/oral/calibrate`) and scores it (WER + fuzzy key-term survival — `lib/speechCalib.js`, no LLM; 2 attempts); (2) **teste de eco** — the server plays a fixed marker sentence in the exam voice (`GET .../echo-audio`, TTS cached) while the student stays silent; the mic capture goes to `POST .../echo-check` and ≥2 markers back = leak (direct measurement of the Rebeca failure mode, through the same audio path the exam will use); (3) **HFP detection** — browser-side (device label + spectral cliff above ~7 kHz, `static/js/soundCheck.js`), always an actionable warning, never a block. The ladder (`lib/soundCheck.js#ladderState`, single source): VERDE proceeds · AMARELO proceeds with a persistent warning (worst result is kept, not just the last — the George case) · VERMELHO (**two hard signals**: 2 readings with WER ≥ 0.6, or echo confirmed twice) does not start alone — the red panel is never a dead end (zero-cost checklist → re-test, hard signals count over the LAST 2 measurements of each probe → reschedule without penalty → professor release, `POST /w/:wt/submissions/:st/waive-soundcheck`, permanent per submission). The professor sees reds in the list BEFORE exam day, with the release button. No sentence ⇒ sound check skipped (fail-open). Same mechanics in the realtime interview (`/live/*`).
- **Proctoring is post-exam and server-side.** The recorded video is analyzed in batch by `lib/proctor.js` (YOLOv8n via `onnxruntime-node`, lazy-loaded so a missing native binary never blocks boot, + a MediaPipe-Hands Python sidecar over ffmpeg). Flags (absence, multiple people, phone, hands) are signals for human review — never auto-accusation. Phone detections pass a **zoom-verify second pass** (crop the box ×2.5, re-infer; only confirmed frames count — gesturing hands near the face are the dominant false positive; raw count kept as `flags.phone.raw_count`). `flags.multiple_people.max_run_sec` records the longest contiguous run (a real second person persists; the student's own arm at the frame edge lasts 1–2 s).
- **Evaluation + batch UI.** `OralExamEvaluatorAgent` grades against the gabarito; the professor panel mirrors the interview (devolutiva + grade, both editable). Batch evaluate/proctor stream per-row progress as NDJSON so the table fills in live.
- **Schema** (migrations 021–040): per-submission `oral_video_key`, `oral_transcript`, `oral_eval_json`, `oral_devolutiva`, `oral_proctor_json`, `oral_voice_json`, `oral_asked_json`, `oral_calibration_json` (speech-calibration pre-test result), plus the shared rubric columns (`grades_json`/`grade_final`/`grade_published_at`; `grades_json.penalty` holds the applied multiplier); `works.kind` + `exam_pdf`/`oral_questions` (`{id, question, answer, rubric, weight, rubric_stale}` — `answer` = optional expected answer, `rubric` = the scoring criterion (5 levels), `rubric_stale` = review flag set when question/answer changes; **stable ids** via `db.setOralQuestions` + monotonic `works.oral_next_qid`, never reusing a deleted id) + `grade_penalty_json` (opt-in penalty policy, shared with the interview) + `works.oral_calibration_json` (the speech-calibration sentence + key terms). `works.oral_grading_mode` is now **vestigial** (single rubric model; kept for the 039 data migration). The professor's two editors (Configuração = pergunta + resposta; Avaliação = peso + rubrica) share one in-memory question list in `oral-professor.html`.

## Agents (oral pipeline)

- **`OralExamExtractorAgent`** — extracts `{question, answer}` from the exam material (PDF via Files API, or TXT inline); fast model. `answer` is always the expected answer (gabarito). The scoring rubric is generated later, from the answer. The answer stays server-side; only questions reach the student's Realtime session.
- **`OralRubricBuilderAgent`** — from `{question, answer}` generates the detailed **rubric** (mini-prompt with 5 levels anchored at 0/2.5/5/7.5/10) + a suggested **weight** by complexity; principal model. Batch (`POST /w/:t/oral/rubrics/generate?scope=stale|all`, NDJSON) or per-question. Requires a non-empty expected answer; the professor can also write the rubric by hand.
- **`OralExamEvaluatorAgent`** — single model (no mode): applies each question's **rubric** to the transcript → a per-question `score` anchored at 0/2.5/5/7.5/10; principal model. Prompt rewards demonstrated understanding (paraphrase/synonyms OK), not matching the gabarito's wording. Evaluate refuses questions without a rubric. Each question is a rubric item with a weight; exam grade = weighted average (`lib/rubric.js#weightedFinal`), stored in `submissions.grades_json`. Seeds the default grade (editable by the professor).
- **`GradePenaltyAgent`** — fixed, opt-in penalty criterion (`works.grade_penalty_json`), applied AFTER the rubric grade: reads the alerts (proctoring/voice for the oral, authorship for the interview, rendered by `lib/gradePenalty.js`) + the professor's policy and returns a 0..1 multiplier; final = base×multiplier, stored in `grades_json.penalty`. Principal model. Also **`StudentFeedbackAgent` is reused for the oral devolutiva** (LLM-generated, guidelines-aware) via a shim in `lib/oralFeedbackOps.js`. Video proctoring can appear as a **soft, non-accusatory note** in the student devolutiva (opt-in, both flows), rendered by `lib/gradePenalty.js#renderProctorForStudent` and governed by `works.devolutiva_proctor_prompt`.
